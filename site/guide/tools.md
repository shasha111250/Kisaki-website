# 工具与权限

支持工具调用的模型可以让 Kisaki 调整表情和动作，也可以获取信息或处理工作区文件。具体工具是否可用，取决于模型能力、配置与当前环境。

## 常见能力

| 能力 | 开始前需要做什么 |
| --- | --- |
| 切换角色表情 / 动作 | 使用提供对应资源的角色与支持工具的模型 |
| 时间、计算等工具 | 在对话中提出请求，由模型选择是否调用 |
| 联网搜索 | 在设置的搜索页面配置提供方、地址和所需 Key，并启用 |
| 工作区文件 / 图片 | 先选择授权工作区，文件路径仍受工作区范围限制 |
| 屏幕观察 | 开启截屏权限，并确认每一次截屏请求 |

## 工作区与文件修改

使用对话界面的工作区入口选择要让 AI 操作的目录，再描述任务。没有设置工作区时，不能把任意本机路径当作已授权范围。

在 **设置 → 权限** 中，**自动执行文件修改** 决定修改是否需要逐次确认。默认保留确认流程更适合第一次使用。开启自动执行后，工作区限制仍有效；修改会自动备份，可在历史中回档。

读取文件的内容或摘要可能成为工具结果并发送给 AI 服务。请根据实际任务选择合适的目录。

## 屏幕观察

1. 打开 **设置 → 权限**，开启 **允许 AI 请求截屏**。
2. 在对话中提出需要屏幕信息的请求。
3. 阅读截屏确认窗口，再决定是否允许。

每次截屏都单独确认；打开开关不会跳过确认。默认截取鼠标所在显示器，并短暂隐藏 Kisaki。截图在内存中处理，发送到你配置的 AI 服务，不写入磁盘、诊断日志或会话快照。

Linux Wayland 下可能受桌面协议限制。

## 本地命令

本地命令执行是开发构建中的实验功能，正式构建由前后端禁用，不应把它当作安装版的常规功能。开发模式即使打开开关，每次执行仍需要确认后端生成的计划。

## 查看执行情况

对话中的工具活动和确认提示会展示调用情况。工具失败时先检查具体错误，不要仅凭角色文字回复认定任务完成。需要详细排障时，在 **设置 → 诊断** 查看本地日志。
